# Contributing to QuizMaster

Thank you for helping improve QuizMaster.

## Before you start

1. Search existing issues before creating a new one.
2. Discuss a substantial change in an issue first.
3. Keep changes focused; do not combine unrelated refactors and features.

## Development workflow

1. Fork the repository and create a branch from `main`.
2. Use a concise branch name such as `fix/jeopardy-steal-order`.
3. Follow the feature-first structure and the conventions in [Development](docs/DEVELOPMENT.md).
4. Run the full validation set before opening a pull request.
5. Describe the user-visible result and the validation performed.

## Code expectations

- Use English for source, comments, documentation, pull requests, and issue discussions.
- Keep German only where it is intentional player-facing UI or game content.
- Prefer readable code with meaningful names, short methods, whitespace, and XML documentation for public or non-obvious APIs.
- Do not commit secrets, generated assets, local databases, or personal test data.

## Reporting bugs and proposing features

Use the issue forms. A useful report includes steps to reproduce, expected behavior, actual behavior, and screenshots or logs when appropriate.
